## 1. Catch2 계약 테스트 작성 요청

### 사용자 요청

```text
[P] 테스트 전문가 입니다.
[C] C++17, CMake, Catch2
[T] 아이템 타입별 최소 5개 테스트를 작성해줘.

    대상 케이스:
    - 정상 변환: meter→feet, meter→yard, feet→meter (역변환)
    - 경계값: value=0 / 매우 큰 수 / 소수점 6자리 정확도
    - 예외: 잘못된 형식 / 음수 / 없는 단위
    - 동적 등록: registerUnit 후 변환
    - 설정 로드: JSON/YAML 정상·실패 케이스

    형식 규칙:
    - Catch2 사용
    - Given-When-Then 주석 구조
    - 각 테스트에 변환 비율 명시 (1 meter = 3.28084 feet)
    - 테스트 이름: test_[변환타입]_[조건]_[기대결과] 형식

[F] 완성된 테스트 코드. cmake -S . -B build && cmake --build build가 Green이 되게 작성.
```

### assistant 진행 기록

```text
요청하신 Catch2 테스트를 기존 CMake 구조에 맞춰 추가하고, 먼저 테스트/빌드 구성을 확인한 뒤 필요한 테스트 파일만 수정하겠습니다. Green 빌드까지 확인해 보겠습니다.

테스트 전문 서브에이전트가 테스트와 CMake 연결을 추가했고, 구현 파일은 건드리지 않았다고 보고했습니다. 이제 제가 변경 내용을 직접 확인하고 빌드 재현 여부를 검증하겠습니다.

현재 저장소는 아직 공개 변환 API가 없어서 테스트는 “계약 테스트” 형태로 작성되어 있습니다. 따라서 컴파일/빌드는 Green을 목표로 확인하고, 실행 테스트는 의도적으로 RED가 될 수 있는 상태인지 분리해서 보겠습니다.

CMake configure와 build는 성공했습니다. 이제 수정 파일 진단과 Git 상태를 확인해서 빌드 산출물이나 기존 사용자 변경사항을 건드리지 않았는지 확인하겠습니다.

진단은 Catch2 헤더와 C++17 설정을 IDE가 아직 해석하지 못해 연쇄 오류를 내고 있지만, 실제 CMake 빌드는 성공했습니다. 그래도 명확한 누락인 `<utility>` include는 보강하겠습니다.

재빌드도 성공했습니다. 빌드 검증으로 생성된 `build/` 디렉터리는 작업 변경사항에 섞이지 않도록 정리하겠습니다.
```

## 2. 결함 목록 문서화 요청

### 사용자 요청

```text
[P] 테스트전문가입니다.
[C] 현재까지 발견된 테스트 실패/결함들을 문서화합니다.
[T] 발견된 결함을 defect_list.md에 정리해줘.

    항목 형식:
    | ID | Severity | 변환 타입 | 재현 절차 | 기대값 | 실제값 | 근본 원인 | 수정 요약 |

    예시:
    | DEF-001 | Critical | meter→feet | "meter:2.5" 입력 | 8.202100 | 0.000000 |
    | if-else 체인에서 feet 분기 누락 | meterValue * 3.28084 추가 |

[F] Markdown. defect_list.md로 저장.
    README의 "RED 단계 To-Do 리스트 > 결함 목록 연결" 체크박스도 업데이트.
```

### assistant 진행 기록

```text
요청하신 결함 문서화를 위해 현재 README의 체크리스트 위치와 테스트 계약 내용을 먼저 확인하겠습니다. 이후 실제 테스트 실패도 재현해서 `defect_list.md`에 근거 있는 결함 목록으로 정리하겠습니다.

README에는 `결함 목록 연결` 체크박스가 아직 미체크 상태이고, 기존 `defect_list.md`는 없습니다. 지금 추가된 계약 테스트를 실행해 실패 유형을 확인한 뒤 결함 ID를 묶어 문서화하겠습니다.

재현 결과, 빌드 자체는 성공하지만 `ctest`에서 36개 계약 테스트가 모두 실패하며 공통 실제값은 `PUBLIC_API_MISSING`입니다. 결함 목록은 개별 테스트를 1:1로 나열하기보다 수정 가능한 근본 원인 단위로 묶어 작성하겠습니다.

`defect_list.md`에는 현재 RED 결과를 결함 원인별로 8개 항목으로 정리하고, README의 결함 목록 생성 체크박스를 체크하겠습니다. 생산 코드는 수정하지 않겠습니다.

README 체크박스는 결함 목록 파일 링크로 업데이트했습니다. 마지막으로 생성된 빌드 산출물을 정리하고 변경 파일 내용을 확인하겠습니다.
```
