## 3. Golden Master 기준 구조

기준 파일은 다음 4개 시나리오를 포함한다.

- `meter:2.5`
- `feet:1.0`
- `yard:1.0`
- `meter:0.0`

각 시나리오는 `[unit:value]` 섹션 헤더, 변환 출력 라인, `---` 구분자로 구성된다.

```text
[meter:2.5]
2.5 meter = 8.202100 feet
2.5 meter = 2.734025 yard
---
[feet:1.0]
1.0 feet = 0.304800 meter
1.0 feet = 0.333332 yard
---
[yard:1.0]
1.0 yard = 0.914403 meter
1.0 yard = 3.000009 feet
---
[meter:0.0]
0.0 meter = 0.000000 feet
0.0 meter = 0.000000 yard
---
```

## 4. Approve 패턴 동작 방식

`tests/generate_golden_master.py`는 다음 순서로 동작한다.

1. 플랫폼에 따라 `build/UnitConverter.exe` 또는 `build/UnitConverter`를 실행 대상으로 선택한다.
2. 각 시나리오를 input file로 기록한다.
3. `subprocess.run(..., stdin=..., stdout=...)` 방식으로 raw stdout을 `build/golden_master/*_actual_raw.txt`에 저장한다.
4. 비교용 `build/golden_master/actual.txt`를 생성한다.
5. `tests/golden_master_expected.txt`가 없으면 현재 actual을 expected로 생성하고 `git add tests/golden_master_expected.txt` 안내를 출력한다.
6. expected가 있으면 actual과 expected를 문자열 그대로 비교한다.
7. 불일치 시 unified diff를 출력하고 exit code `1`로 실패한다.
8. 일치 시 `Golden master approved.`를 출력하고 성공한다.

## 7. 한계 및 주의

- 현재 스크립트는 stdout raw 캡처 파일도 보관하지만, expected 비교 구조는 요청된 섹션 형식으로 정규화한다.
- raw stdout 파일과 `actual.txt`는 `build/golden_master/` 아래 생성되며 커밋 대상이 아니다.
- Golden Master는 현재 콘솔 출력 형식을 승인 기준으로 고정하므로, 의도적인 출력 변경이 있을 경우 expected 갱신 절차가 필요하다.
- 전체 CTest 결과는 이전 RED 스켈레톤 대상의 의도된 실패와 별개로 판단해야 한다.
