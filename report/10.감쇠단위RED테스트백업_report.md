## 1. 작업 목적

UnitConverter C++ 프로젝트의 신규 기능 후보인 동적 단위 등록 확장을 TDD RED 단계로 고정했다. 구현은 추가하지 않고, `registerUnit("cubit", 0.4572)` 이후 기대해야 하는 변환 계약과 기존 `meter -> feet` 회귀 보호를 Catch2 테스트로 작성하는 것이 목적이다.

이번 백업은 다음 원칙을 따른다.

- 구현 금지 요구사항에 따라 생산 구현은 작성하지 않았다.
- `src/DecayingUnit.cpp`는 RED 단계 placeholder만 포함한다.
- `build/`, `build-coverage/`, `*.gcov` 등 기존 또는 테스트 실행 산출물은 커밋하지 않는다.
- 접근 가능한 parent 대화 원문은 `/prompt`에 JSONL 원문으로 보존한다.
- README와 PRD의 동적 단위 등록, meter hub 변환, 회귀 보호 규칙과 연결한다.

## 4. 테스트 및 검증 결과

실행한 검증:

- 명령: `cmake -S . -B build`
  - 결과: 통과.
- 명령: `cmake --build build --target test_decaying_unit`
  - 결과: 통과.
- 명령: `ctest --test-dir build -R test_decaying_unit --output-on-failure`
  - 결과: 의도된 RED 실패.
  - 최종 재확인 결과: `test_decaying_unit` 1개 테스트 타깃 실패, `0% tests passed, 1 tests failed out of 1`.
- 도구: `ReadLints`
  - 결과: `tests/test_decaying_unit.cpp`에서 IDE clang 진단이 발생했다.
  - 원인: IDE 진단이 Catch2 include 경로를 찾지 못해 `catch2/catch_approx.hpp file not found` 및 파생 파싱 오류를 보고했다.
  - 판단: 실제 CMake 빌드로 `test_decaying_unit` 컴파일은 통과했으므로 RED 테스트 빌드 검증은 완료했다.

의도된 실패 항목:

- BT-02: `convert("meter", 1.0, "cubit")`가 `0.0`을 반환해 기대값 `1.0 / 0.4572`와 불일치.
- BT-03: `convert("cubit", 1.0, "feet")`가 `0.0`을 반환해 기대값 `0.4572 * 3.28084`와 불일치.
- BT-04: 음수 비율 등록 시 예외가 발생하지 않음.
- BT-05: `convertAll("cubit", 1.0)` 결과가 3개만 반환되어 기대한 4개 단위와 불일치.

미실행:

- `ctest --test-dir build` 전체 실행은 이번 RED 검증의 필수 조건으로 실행하지 않았다.
  - 사유: 이번 작업의 목적은 신규 bonus 기능 RED 실패를 고정하는 것이며, 기존 작업 이력상 별도 스켈레톤/산출물 상태가 존재한다.
