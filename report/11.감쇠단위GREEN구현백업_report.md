## 1. 작업 목적

UnitConverter C++ 프로젝트의 동적 단위 등록 기능을 TDD GREEN 단계로 최소 구현했다. 이전 RED 단계에서 고정한 `registerUnit("cubit", 0.4572)` 계약을 통과시키되, REFACTOR는 수행하지 않는 것이 이번 작업의 목적이다.

이번 백업은 다음 원칙을 따른다.

- GREEN 구현 범위는 `Converter.cpp`의 단위 registry 기반 변환으로 제한했다.
- 이전 RED 단계에서 추가된 테스트와 산출물은 이번 GREEN 단계에서 수정하지 않았다.
- `build/`, `build-coverage/`, `*.gcov` 등 빌드/커버리지 산출물은 커밋하지 않는다.
- 접근 가능한 현재 요청 원문은 `/prompt`에 JSONL 원문으로 보존한다.
- GREEN 구현을 수행한 step-by-step parent transcript 원문은 현재 subagent 입력에 제공되지 않아, parent가 전달한 현재 요청 원문만 보존했다.

## 2. 변경 파일

구현 변경:

- `Converter.cpp`
  - `UnitRegistry`를 추가해 기본 단위 `meter`, `feet`, `yard`와 `registerUnit()` 등록 단위를 같은 registry에서 조회하도록 했다.
  - `registerUnit(name, ratioToMeter)`에서 `ratioToMeter <= 0.0`이면 `std::invalid_argument`를 발생시킨다.
  - `convert()`가 from/to 단위의 `ratioToMeter`를 찾아 `from -> meter -> to` 흐름으로 변환한다.
  - `convertAll()`이 registry에 등록된 모든 단위를 순서대로 반환한다.

이번 GREEN 단계에서 수정하지 않은 파일:

- `tests/test_decaying_unit.cpp`
  - RED 단계의 BT-01~BT-06 테스트를 그대로 사용했다.
- `tests/test_converter.cpp`
  - 기존 TC-A/TC-B 회귀 테스트를 그대로 사용했다.
- `tests/unit_converter_contract_tests.cpp`
  - 기존 `FAIL("RED")` placeholder는 이번 GREEN 범위 밖이므로 수정하지 않았다.

백업 산출물:

- `prompt/11.감쇠단위GREEN구현백업_prompt.md`
  - 현재 접근 가능한 보고서 작성 요청 원문을 JSONL 형식으로 보존한다.
- `report/11.감쇠단위GREEN구현백업_report.md`
  - 작업 목적, 변경 파일, 요구사항 연결, 테스트 결과, 미완료 항목, 백업 결과를 기록한다.

## 3. 요구사항 연결

- `README.md`
  - 새 단위 추가 시 기존 `meter`, `feet`, `yard` 회귀 테스트를 다시 실행한다는 가이드와 연결된다.
  - `feet`와 `yard` 간 변환은 직접 비율이 아니라 `meter` 기준값을 경유한다는 규칙과 연결된다.
- `docs/PRD.md`
  - §3.1 동적 단위 등록 및 단위 레지스트리 요구사항과 연결된다.
  - §3.3 동적 등록 비율은 `0`보다 커야 한다는 제약을 구현했다.
  - §4.4 모든 단위는 meter 기준 비율로 표현한다는 확장성 원칙을 구현했다.
  - §7.2 새 기능 추가 시 기존 기본 단위 변환 테스트를 함께 실행한다는 회귀 보호 규칙과 연결된다.
