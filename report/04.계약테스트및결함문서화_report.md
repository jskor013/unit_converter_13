## 3. 요구사항 연결

- `README.md`
  - 기본 단위 `meter`, `feet`, `yard`와 기준 비율을 계약 테스트의 기대값으로 사용했다.
  - 입력 형식 `<unit>:<amount>`, 음수 거부, 미지원 단위 오류, 출력 포맷 보존 규칙을 테스트 대상으로 고정했다.
  - RED 단계 결함 목록 연결 항목을 실제 `defect_list.md`와 연결했다.
- `docs/PRD.md`
  - Domain 라인 커버리지 `95%`, Boundary 오류 코드 검증률 `100%`, 설정 실패 유형 구분, 동적 단위 등록 후 회귀 보호 요구를 테스트 범위에 반영했다.
  - JSON/CSV/Table 출력 스키마와 원 입력 보존 규칙을 출력 포맷 계약 테스트에 반영했다.
- 사용자 요청
  - Catch2, C++17, CMake 조건에 맞춰 테스트 인프라를 추가했다.
  - 테스트 이름은 `test_[변환타입]_[조건]_[기대결과]` 형식으로 작성했다.
  - 발견 결함은 지정된 Markdown 표 형식으로 `defect_list.md`에 저장했다.
  - 빌드 산출물 `build/`는 작업 변경사항에 포함하지 않도록 정리했다.

## 4. 테스트 및 검증 결과

실행 또는 확인된 검증:

- `cmake -S . -B build`: 성공
- `cmake --build build`: 성공
- `cmake --build build` 재빌드: 성공
- `ctest --test-dir build --output-on-failure`: 실패 재현
- 실패 요약: Catch2 계약 테스트 36개 실패
- 공통 실제값: `PUBLIC_API_MISSING`
- `ReadLints`: `README.md`, `defect_list.md` 문서 진단 오류 없음
- `git status --short`: 관련 변경 파일과 기존 사용자 변경 가능 파일을 확인했다.
- `git diff`: README 체크박스 변경과 기존 `.cursor/agents/report-backup-agent.md` 변경을 확인했다.
- `git log --oneline -5`: 최근 커밋 메시지 스타일을 확인했다.

미실행:

- `gcov`/`lcov` 커버리지 측정은 실행하지 않았다.
- 사유: 현재 계약 테스트가 RED 상태이며 생산 공개 API가 아직 없어 커버리지 목표를 측정할 단계가 아니다.

- `parse`, `convert`, `registerUnit`, `loadConfig`, `format` 공개 API 구현은 아직 없다.
- Boundary, Control, Entity, Data 계층 분리는 아직 생산 코드에 반영되지 않았다.
