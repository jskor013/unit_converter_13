## 5. 테스트 및 검증 결과

각 GREEN 커밋에서 수행한 검증:

- `cmake -S . -B build && cmake --build build`
  - RED 또는 빌드 실패 상태 확인에 사용했다.
- `ctest --test-dir build -R test_converter --output-on-failure`
  - 대상 GREEN 테스트 통과 확인에 사용했다.

최종 확인:

- 명령: `ctest --test-dir build -R test_converter --output-on-failure`
- 결과: `100% tests passed, 0 tests failed out of 1`
- 대상: `test_converter`
- 의미: GREEN 단계에서 작성한 focused 테스트 대상은 PASS 상태다.

별도 RED 산출물:

- `unit_converter_contract_tests`
  - 이전 RED 단계의 스켈레톤 테스트이며 각 본문이 `FAIL("RED");`로 유지된다.
  - 전체 `ctest`에서는 이 대상 때문에 의도적으로 실패할 수 있다.

IDE 진단:

- clangd가 Catch2 include 경로를 찾지 못하는 진단을 표시할 수 있다.
- CMake configure/build 기준으로는 Catch2가 정상 해석되어 빌드와 `test_converter` 실행이 통과했다.

## 6. 미완료 항목 및 리스크

- 현재 구현은 GREEN 최소 구현이며 중복 제거, 책임 분리, API 정리, 예외 메시지/오류 코드 구조화는 REFACTOR 단계로 넘긴다.
- `Converter.cpp`는 아직 단일 파일 중심이며 Boundary/Control/Entity 레이어 분리는 완료되지 않았다.
- `loadConfig`는 유효 설정 로드 테스트를 통과시키는 최소 범위 구현이다.
- TC-A-07, TC-B-07은 probe 결과 이미 PASS였기 때문에 strict TDD 원칙에 따라 신규 커밋을 만들지 않았다.
- 전체 CTest는 RED 스켈레톤 대상이 포함되어 실패할 수 있으므로 GREEN 검증 범위는 `test_converter`로 분리한다.
