# PRD: 확장 가능한 C++ 단위 변환 학습 시스템

## 1. 프로젝트 개요

### 1.1 한 줄 목적문

C++/클린 아키텍처 학습자가 길이 단위 변환 문제를 통해 계약 정의, 테스트 우선 개발, 레이어 분리, 회귀 보호를 학습한다.

### 1.2 배경 및 문제 정의

이 프로젝트는 `meter`, `feet`, `yard` 변환이라는 작은 도메인을 사용해 단순 계산이 아닌 소프트웨어 계약 설계를 학습하는 과제다. 학습자는 입력 형식, 음수 정책, 미지원 단위 처리, 변환 비율, 출력 표현을 먼저 고정하고 이를 테스트로 검증해야 한다. 핵심 문제는 변환 알고리즘 자체가 아니라, 요구사항 변경과 새 단위 추가에도 기존 동작이 깨지지 않도록 Boundary, Control, Entity 책임을 분리하는 것이다.

### 1.3 목표

- Domain 테스트 라인 커버리지 `95%` 이상, 분기 커버리지 `90%` 이상을 달성한다.
- Boundary 계약 테스트에서 입력 오류, 출력 포맷, 오류 코드 검증률 `100%`를 달성한다.
- README 기준 비율 `1 meter = 3.28084 feet`, `1 meter = 1.09361 yard`를 회귀 테스트로 보호한다.
- 새 단위 등록 후 기존 `meter`, `feet`, `yard` 변환 결과가 허용 오차 `0.000001` 이내로 유지됨을 검증한다.
- 설정 로드 실패를 파일 없음, 형식 오류, 스키마 오류, 비율 오류로 구분해 테스트한다.

### 1.4 비목표

- GUI, 웹 API, 데이터베이스 연동은 이 프로젝트 범위에 포함하지 않는다.
- 무게, 온도, 통화 등 길이 외 도메인 변환은 포함하지 않는다.
- 고성능 수치 계산이나 국제 단위 표준 전체 지원은 목표로 하지 않는다.

| 입력 파싱 | `<unit>:<amount>` 형식만 허용한다. 예: `meter:2.5` | 성공 시 단위명과 숫자값이 분리된 상태로 다음 단계에 전달된다. |

| 원 입력 보존 | 정상 변환 가능한 입력. 예: `meter:2.5` | 모든 출력 표현에 원 입력 값 `2.5`와 원 입력 단위 `meter`가 포함된다. |
| 설정 로드 실패 | 잘못된 설정 상태. 예: 파일 없음, 파싱 불가, 필수 필드 누락, 비율 `0` 이하 | 설정 오류 코드가 반환되고 변환 유스케이스는 시작되지 않는다. |
| 동적 단위 등록 | `register:<unit>:<meter_ratio>` 형식. 예: `register:cubit:0.4572` | 등록 성공 메시지 또는 등록 실패 오류를 반환한다. |
| JSON 출력 | 변환 결과와 출력 포맷 `json` 요청 | `source`, `results`, `format`을 포함한 JSON 문자열을 반환한다. |

## 4. 비기능 요구사항

### 4.1 기술 스택

- 언어: C++17 이상
- 빌드 시스템: CMake
- 테스트 프레임워크: Catch2

### 4.2 아키텍처 원칙

- Boundary는 입력 파싱, 출력 직렬화, 오류 표현만 담당한다.
- Control은 유스케이스 흐름을 조정한다.
- Entity는 단위 정의, 변환 규칙, 불변식을 담당한다.
- 의존성 방향은 `Boundary -> Control -> Entity`를 따른다.
- 저장소 세부사항은 Entity가 알지 않는다.
- 새 단위 추가는 기존 변환 분기 수정을 요구하지 않아야 한다.

### 4.3 테스트 커버리지 목표

| 영역 | 목표 |
|---|---|
| Domain | 라인 `95%` 이상, 분기 `90%` 이상 |
| Boundary | 라인 `90%` 이상, 오류 코드별 테스트 `100%` |
| Data | 라인 `85%` 이상, 설정 실패 유형별 테스트 `100%` |
| Integration | 정상 경로 `3개` 이상, 실패 경로 `5개` 이상 |

### 4.4 확장성 원칙

- 모든 단위는 meter 기준 비율로 표현한다.
- 새 단위 등록은 기존 기본 단위 변환 결과를 변경하지 않아야 한다.
- 출력 포맷 추가는 Domain 테스트 변경을 요구하지 않아야 한다.
- 설정 저장 방식 변경은 변환 규칙 테스트 변경을 요구하지 않아야 한다.

## 5. 데이터 요구사항

### 5.1 단위 비율 상수

| 단위 | meter 기준 계약 |
|---|---|
| meter | `1 meter = 1 meter` |
| feet | `1 meter = 3.28084 feet` |
| yard | `1 meter = 1.09361 yard` |

### 5.2 설정 외부화 방식

- 기본값은 메모리 내 기본 단위 정의로 제공할 수 있다.
- 확장 설정은 JSON 또는 YAML 중 하나로 로드한다.
- 설정 파일이 없으면 설정 없음 오류를 반환한다.
- 설정 형식이 파싱 불가능하면 설정 파싱 오류를 반환한다.
- 단위명이 비어 있거나 비율이 `0` 이하이면 설정 검증 오류를 반환한다.

### 5.3 동적 단위 등록 계약

- 등록 입력 형식은 `register:<unit>:<meter_ratio>`로 고정한다.
- `<unit>`은 비어 있으면 실패한다.
- `<meter_ratio>`는 `0`보다 큰 숫자여야 한다.
- 이미 등록된 단위명은 중복 등록 오류로 거부한다.
- 등록 성공 후 해당 단위는 변환 대상 목록에 포함된다.

## 6. 출력 요구사항

### 6.1 콘솔 기본 포맷

- 출력은 원 입력 값, 원 입력 단위, 변환 값, 대상 단위 순서를 유지한다.
- 기본 표현은 `<source_amount> <source_unit> = <converted_amount> <target_unit>`이다.
- 소수 비교 허용 오차는 `0.000001`로 테스트한다.
- 출력에는 원 입력 값과 원 입력 단위가 보존되어야 한다.

### 6.2 JSON 출력 스키마

| 필드 | 계약 |
|---|---|
| `status` | 성공 시 `success` |
| `source.amount` | 원 입력 숫자 값 |
| `source.unit` | 원 입력 단위 |
| `results[].targetUnit` | 대상 단위명 |
| `results[].value` | 변환 숫자 값 |
| `format` | `json` |

### 6.3 CSV 출력 스키마

| 컬럼 순서 | 컬럼명 | 계약 |
|---|---|---|
| 1 | `source_amount` | 원 입력 숫자 값 |
| 2 | `source_unit` | 원 입력 단위 |
| 3 | `target_unit` | 대상 단위명 |
| 4 | `converted_amount` | 변환 숫자 값 |

### 6.4 표 출력 스키마

| 컬럼 | 계약 |
|---|---|
| Source Amount | 원 입력 숫자 값 |
| Source Unit | 원 입력 단위 |
| Target Unit | 대상 단위명 |
| Converted Amount | 변환 숫자 값 |

## 7. 성공 지표

### 7.1 인수 기준

- [ ] `meter:1` 입력 결과에 `3.28084 feet`와 `1.09361 yard`가 허용 오차 `0.000001` 이내로 포함된다.
- [ ] `meter`, `meter:abc`, `meter:-1`, `mile:1` 입력은 각각 고정 오류 코드로 실패한다.
- [ ] JSON, CSV, Table 출력은 정의된 필드와 순서를 만족한다.
- [ ] 설정 형식 오류가 발생하면 변환 유스케이스는 실행되지 않는다.
- [ ] 새 단위 등록 후 기존 `meter`, `feet`, `yard` 회귀 테스트가 통과한다.

### 7.2 회귀 보호 규칙

- README 기준 비율은 명시적 변경 승인 없이 수정하지 않는다.
- 오류 코드와 메시지 패턴은 계약 테스트 없이 변경하지 않는다.
- 입력 형식 `<unit>:<amount>`는 계약 테스트 없이 변경하지 않는다.
- 출력의 원 입력 값과 원 입력 단위 보존 규칙은 변경하지 않는다.
- 새 기능 추가 시 기존 기본 단위 변환 테스트를 함께 실행한다.

## 8. 용어 정의

| 용어 | 정의 |
|---|---|
| Unit | `meter`, `feet`, `yard`처럼 변환 가능한 길이 단위 |
| Source Unit | 사용자가 입력한 원 단위 |
| Target Unit | 변환 결과로 계산되는 대상 단위 |
| Meter Hub | 모든 단위 변환이 meter 기준값을 경유하는 규칙 |
| Registry | 등록된 단위명과 meter 기준 비율을 관리하는 목록 |
| Boundary | 입력, 출력, 오류 표현을 담당하는 바깥 레이어 |
| Control | 변환과 등록 유스케이스 흐름을 조정하는 레이어 |
| Entity | 변환 규칙과 도메인 불변식을 보유하는 레이어 |
| Contract Test | 입력, 출력, 오류 코드 같은 외부 계약을 검증하는 테스트 |
| Regression Protection | 기존 기준 비율과 오류 계약이 깨졌을 때 테스트로 감지하는 정책 |
